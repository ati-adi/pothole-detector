# Детектор ям на дорогах (MVP)

Нейросеть находит ямы на фото и видео дороги, оценивает их опасность и ставит точки на карту.

```
фото / видео с телефона или регистратора
        │
        ▼
  YOLO26n (дообучена на 1 243 фото ям)  ──►  рамки + уверенность
        │
        ├─ видео: трекинг → одна яма считается один раз, а не в каждом кадре
        ├─ опасность: низкая / средняя / высокая (по доле кадра, которую занимает яма)
        └─ GPS: из EXIF фото или геолокации браузера
        │
        ▼
  отчёт JSON / GeoJSON  +  веб-карта
```

## Быстрый старт

Готовая модель лежит в репозитории (`models/pothole.onnx`), обучать заново не нужно.

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python detect.py road.jpg dashcam.mp4  # результат в output/
uvicorn app:app                        # веб-демо на http://127.0.0.1:8000
```

Обучение (нужен PyTorch, ставится отдельно):

```bash
pip install -r requirements-train.txt
python train.py   # скачает датасет, обучит, сохранит models/pothole.pt и экспортирует models/pothole.onnx
```

На Mac с Apple Silicon обучение идёт на GPU (MPS), на ПК с NVIDIA — на CUDA, иначе на CPU.

## Архитектура

Обучение — Ultralytics/PyTorch. Работа приложения — **ONNX Runtime без PyTorch**: зависимости ~300 МБ вместо
~1.1 ГБ, фото обрабатывается за ~20 мс на CPU. Поэтому одно и то же ядро работает и локально, и в
serverless-функции на Vercel. Качество ONNX-версии совпадает с PyTorch (F1 0.683 против 0.687 — разница
от интерполяции при ресайзе).

| Файл | Что делает |
|---|---|
| `pothole_ai.py` | ядро: ONNX-инференс + NMS, трекер ям на видео, оценка опасности, GPS из EXIF |
| `detect.py` | CLI: фото, видео, папки → размеченные файлы, `report.json`, `potholes.geojson` |
| `app.py` + `static/index.html` | веб-демо: загрузка файла, результат, карта всех найденных ям |
| `storage.py` | где хранится карта: локально — папка `data/`, на Vercel — Vercel Blob |
| `train.py` | скачивает датасет, делит на train/val (85/15), дообучает YOLO, экспортирует ONNX |

## Деплой на Vercel

Проект деплоится как Python-функция (FastAPI определяется автоматически). Карта хранится в Vercel Blob:
снимок — `images/<id>.jpg`, точка — `reports/<время>_<id>.json`.

```bash
vercel link
vercel blob create-store pothole-map --access public   # и подключить к проекту
vercel deploy --prod
```

Ограничение Vercel — 4.5 МБ на запрос. Крупные фото страница сама уменьшает до 2560 px перед отправкой
(GPS из EXIF при этом теряется — включите геолокацию). Видео на сайте — до 4.5 МБ (несколько секунд);
длинные записи обрабатывайте локально через `detect.py`.

## Качество модели

YOLO26n, 50 эпох, 640 px, Apple M5 (MPS) — 37 минут. Валидация: 186 фото / 533 ямы, не участвовавших в обучении.

| Метрика | Значение |
|---|---|
| mAP50 | 0.708 |
| mAP50-95 | 0.382 |
| Precision при пороге 0.35 | 0.78 — из 100 найденных рамок 78 действительно ямы |
| Recall при пороге 0.35 | 0.61 — находит 61% размеченных ям |
| F1 | 0.687 |
| Размер модели | 9.8 МБ (ONNX) |

Порог 0.35 выбран по максимуму F1 на валидации. Ниже порог — больше находок и больше ложных срабатываний
(0.2 → P 0.63 / R 0.69), выше — наоборот (0.5 → P 0.81 / R 0.55). В веб-демо это ползунок «Чувствительность».

Recall занижен строгостью проверки: засчитывается только рамка с IoU ≥ 0.5, а в разметке датасета
группа ям иногда обведена одной рамкой, иногда каждая отдельно.

В `examples/` лежат фото из валидации; в `gps_photo.jpg` GPS дописан вручную для проверки карты,
координаты условные. `dashcam_sim.mp4` — синтетическое «видео», склеенное из этих фото.

## Ограничения текущей версии

- **Опасность — эвристика.** Считается по доле кадра, которую занимает рамка. Реальные размеры в сантиметрах
  требуют калибровки камеры (высота крепления, угол наклона) или стереокамеры / LiDAR.
- **Датасет собран из интернета** (в основном индийские дороги). Для своего города модель нужно дообучить
  на местных снимках: зимние ямы, лужи, снег, ночь, разметка, люки и заплатки дают ложные срабатывания.
- **Видео не знает координат каждого кадра.** Для карты по видео нужен GPS-трек (GPX регистратора или
  телефона), который сопоставляется с временем кадра.
- Геолокация браузера работает на `localhost` или по HTTPS; с телефона по локальной сети нужен HTTPS.
- **Карта публичная.** Снимки с найденными ямами и координатами видны всем, кто открыл сайт; модерации нет.
- **Лицензия.** Модель обучена через Ultralytics (AGPL-3.0). Для закрытого коммерческого продукта нужна их
  Enterprise-лицензия или переобучение на детекторе под Apache-2.0.

## Куда развивать

1. **Свои данные.** 300–500 размеченных кадров с местных дорог дадут больше, чем любая смена архитектуры.
   Разметка: CVAT, Label Studio или Roboflow → формат YOLO → `datasets/potholes`.
2. **Мобильное приложение.** Экспорт модели `yolo export model=models/pothole.pt format=coreml` (iOS) или
   `format=tflite` (Android): телефон на торпеде в реальном времени пишет ямы с GPS. Промежуточный шаг —
   ONNX-модель прямо в браузере (onnxruntime-web): камера телефона, без загрузки видео на сервер.
3. **Акселерометр.** Удар подвески + детекция камерой = почти без ложных срабатываний; без камеры —
   дешёвый вариант для таксопарков и автобусов.
4. **Сбор с многих машин.** Сервер объединяет точки в радиусе ~10 м в одну яму, считает число подтверждений
   и «возраст» ямы, отдаёт карту и выгрузку для дорожных служб.
5. **Сегментация вместо рамок** (`yolo26n-seg`) — площадь ямы по маске точнее, чем по рамке.
